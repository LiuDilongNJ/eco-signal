## 选择正确的管理范围

权限按项目和集合路径判断。应授予成员完成工作所需的最小范围。

| 角色或权限 | 管理能力 |
| --- | --- |
| 系统管理员 | 绕过访问检查，管理系统级设置和用户 |
| `project:write` | 管理项目、其集合以及全部集合范围资源 |
| `collection:write` | 管理一条集合路径及其集合范围资源 |
| 资源权限，例如 `audio:write` | 仅管理已授予范围内的该资源类型 |
| 读权限 | 查看已授予资源；写权限同时满足读权限 |

项目层资源权限会覆盖该项目下所有集合。`project:write` 覆盖项目中的集合和资源访问，`collection:write` 覆盖其子资源访问。父级写权限已覆盖的低层权限不应重复保存。

只有系统管理员可以授予 `project:write`。项目或集合管理者只能在自己管理的范围内委派权限。

## 管理项目和集合

在对应的 Data 视图中创建项目和集合。只有具有项目管理权限的用户可将集合关联到项目。媒体、站点、标注、审核和任务应位于其实际所属的集合范围内。

分配用户时，需要区分显式授予和继承访问：

- 项目读权限会使项目可见，但不会将每个集合都选为集合读者。
- 集合读权限还需要父项目读权限。
- 项目管理权限已覆盖所有集合，不应再添加重复的集合管理权限。

请在授予访问前，使用项目和集合视图检查关联关系和范围。

## 管理用户和权限

通过 Users 和权限控制添加成员，并分配项目或集合访问。权限编辑器会同时显示已保存的权限和继承后的有效访问；保存时只提交该项目或集合显式选择的权限。

日常工作应只授予所需资源的读或写权限。成员需要管理集合中全部资源时使用集合管理权限；只有需要管理整个项目时才使用项目管理权限。项目与集合关联变化后应重新检查访问，因为集合授权受项目路径限制。

## 配置公开访问

公开访问仅提供读权限，且两个层级都必须正确配置：

- 项目公开本身不会公开其集合或媒体。
- 公共项目内集合的 `public_access` 会允许匿名读取该集合、其音频和站点。
- 公共项目内集合的 `public_tags` 会允许匿名读取标注。
- 两个公开选项都不会授予写权限。

共享公开项目链接前请复核这些设置，尤其是标注可能包含敏感观测信息时。

## 维护设置和数据

Settings 区域包含个人资料和偏好、传感器记录、记录器、麦克风、相机、镜头、分类单元、声音、服务器设置和系统日志。系统专用标签仅系统管理员可见。

请在项目工作需要前维护共享参考数据。优先更新既有记录，避免创建近似重复项；使用筛选和导出检查数据集。网络设置属于运行控制，仅授权管理员可修改。

## 使用批量数据导入

用户操作流程请参阅[用户指南](user-guide.zh.md)，本节说明排障和权限所需的运行约定。

支持的资源包括项目、集合、站点、媒体、标注、审核、索引日志、任务、用户、记录器、麦克风、相机、镜头、分类单元和声音分类记录；Queue 不支持导入。标准导入使用 `POST /api/v1/{resource}/imports` 的 `multipart/form-data`；集合包使用专门的导入流程。

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `file` | 是 | UTF-8 或 UTF-8-BOM `.csv`、`.txt`、`.json`；最大 20 MiB、50,000 条记录、256 列 |
| `dry_run` | 否，默认 `true` | `true` 只校验；`false` 仅在所有非跳过行有效时提交 |
| `project_id` | 依范围而定 | 用于访问检查的正项目 ID |
| `collection_id` | 依范围而定 | 正集合 ID；集合范围资源必填 |
| `media_type` | 仅媒体 | `audio` 或 `photo`，用于选择元数据 schema |

校验响应会提供来源格式、总数、成功数、跳过数、失败数、提交状态、逐行结果和全局错误。校验报告是临时结果，不会保存。项目导入需要系统管理员；集合导入需要 `project:write`；集合范围资源导入需要所选项目和集合路径上的对应资源写权限。公开读权限不能用于导入。

例如，分号分隔文件可以是：

```text
name;brand;version
Forest recorder;Example;2
```

TXT 文件也可以使用 JSON 对象数组：

```json
[
  {"name": "Forest recorder", "brand": "Example", "version": "2"}
]
```

成功校验会返回 HTTP 200 和临时报告，例如：

```json
{
  "code": 0,
  "message": "Import validation completed",
  "data": {
    "source_format": "delimited_text",
    "delimiter": ";",
    "dry_run": true,
    "total": 1,
    "succeeded": 1,
    "skipped": 0,
    "failed": 0,
    "committed": false,
    "rows": [{"row_number": 2, "status": "succeeded", "field": null, "reason": null}],
    "global_errors": []
  }
}
```

接口不会返回导入的密码值，也不会在逐行错误中包含密码。模板包含准确的表头和一行示例数据。Settings 主数据导入仍仅限系统管理员。离线集合包接口为 `POST /api/v1/data-imports`。

## 使用 Queue 和监控

Queue 是后台上传、分析、导入、导出等工作的运行依据。请根据状态、数量、警告和错误判断是否需要处理，不要只根据上传抽屉判断任务是否完成。

服务健康、错误报告、指标和仪表盘请参阅[可观测性操作文档](observability.zh.md)。生产环境应通过内部网络或网关保护指标。部署、迁移和恢复流程请参阅[运维指南](operations-guide.zh.md)。
